# Final security threat model

This audit models Fitness OS as a public educational application with optional browser-local records. It has no accounts, authentication, payments or personal cloud sync. The production origin observed during this pass is https://kaush-ka-gym.vercel.app. Sharing a browser profile shares its data; local records are not an access-controlled multi-user system.

## Assets and boundaries

Private assets: workout history, nutrition logs, diet targets, personal recipes, sleep/recovery records, cardio sessions, supplement records, body measurements, progress photos, recent searches, favourites/collections and personal notes. Backup files and CSV exports become private files under the owner's custody after download. Public knowledge, source references and manifests are repository-owned assets.

Boundaries: browser DOM ↔ IndexedDB; browser ↔ small localStorage preferences/session control; imported file ↔ validated canonical records; local records ↔ exported files; browser ↔ public SSR/Vercel runtime/static assets; user-initiated external source links and consented YouTube privacy-enhanced frames; GitHub source/Actions ↔ dependencies/build output ↔ owner-controlled Vercel deployments.

## Threat assessment

| Threat                                    | Applicability, controls and residual risk                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| XSS / HTML injection                      | Applicable to notes, names, search and imported text. React escapes text; only a static nonced theme initializer inserts HTML. Synthetic payload browser checks exercise user text. CSP is defense in depth, not a substitute for escaping.                                                                                                                                                            |
| Unsafe URL / open redirect                | Imported provenance must use bounded HTTP(S) URLs. Application redirects use fixed internal routes or repository-owned migrations. Public-origin configuration rejects credentials, paths, queries and fragments. Public source links use reviewed repository URLs.                                                                                                                                    |
| CSRF / SQL injection / account takeover   | No credentialed account writes or SQL/database API exist. TanStack server-function requests retain CSRF middleware; no account/authentication attack surface is invented.                                                                                                                                                                                                                              |
| Network, URL or SSR data leakage          | Structured records remain in browser databases; no remote personal sync, telemetry or fitness API. Public search URL parameters are public queries; private search stays off URLs. Synthetic network and independent SSR probes test markers. Owner must avoid typing private information into explicitly public query/link fields.                                                                    |
| Malicious import / excessive resources    | File and decompressed backup limit 100 MiB. Iterative object traversal bounds nesting to 64, strings to 3 million characters and traversal to 12 million values before recursive validation/hashing. Owning schemas, finite numbers, unique IDs, relationships, format versions and hashes precede canonical writes. Limits may reject exceptional archives; selected-module export remains available. |
| Storage corruption / races / stale writes | Owning ordered migrations, blocked/cancelled upgrade handling, version-change close, editor/restore coordination and transactional module writes. Browser quota, eviction, extensions or user tampering remain possible.                                                                                                                                                                               |
| Interrupted multi-database restore        | Before-image journal, automatic rollback attempt, retained recovery when blocked. No global multi-database atomicity is claimed. Back up externally before replacement.                                                                                                                                                                                                                                |
| CSV formula execution                     | Spreadsheet-safe mode neutralizes = + - @ tab and CR prefixes and quotes text. Raw mode remains explicitly identified; opening raw files in spreadsheet software is an owner choice.                                                                                                                                                                                                                   |
| Photo metadata / spoofed media            | MIME and magic bytes checked before decoding; 10 MiB/20 MP bounds; canvas sanitized copy removes original metadata. Binary restore verifies sanitized format, metadata, checksum, dimensions and manifest. Ordinary portable backup excludes photo binary. Device decoders remain an upstream trust boundary.                                                                                          |
| Dependency / install-script compromise    | Lockfile, integrity checks, fresh installs and current npm audit; no blanket upgrades. esbuild's reviewed postinstall selects/verifies its native binary. Registry/toolchain compromise is residual risk; audit is not a supply-chain guarantee.                                                                                                                                                       |
| Secret disclosure                         | Only public origin is expected. Pattern scans cover current tracked files, public output and all fetched reachable historical blobs without printing matches. No history rewriting. Binary strings scanned; screenshot OCR and inaccessible history are outside coverage.                                                                                                                              |
| GitHub Actions / release compromise       | Commit-pinned actions, contents:read, no pull_request_target, no deployment job, no repository metadata shell interpolation. Recommend protected main and required review/checks. Git deployment remains disabled; no production release is authorized by this pass.                                                                                                                                   |
| Origin/profile migration                  | Browser storage is isolated by origin/profile. Deployment/domain changes do not migrate IndexedDB. Export and verify restore before changing origin or profile.                                                                                                                                                                                                                                        |
| Backup disclosure / integrity assumptions | Backups are unencrypted and not authenticated. SHA-256 detects corruption, not malicious authorship. Do not publish backup/CSV/photo files or personal test traces.                                                                                                                                                                                                                                    |
| Inline styles                             | React body-region positioning, media limits and source layouts use style attributes. Keep narrow style-src-attr allowance; script unsafe-inline/eval remain disallowed. Removing style permission without replacing those layouts would regress the app.                                                                                                                                               |

## Release interpretation

The existing production build contains a caught, CSP-blocked Zod eval capability probe. It does not execute dynamic code and falls back to interpretation. The candidate browser build configures jitless before schema initialization; direct event checks cover this. The live audit records the known probe rather than describing production as having zero policy events.

Automated checks establish evidence for a specific commit/build and synthetic scenarios, not formal penetration testing, full WCAG conformance or clinical review. Real devices, assistive technology, file pickers, quota/eviction and backup custody require owner testing. New runtime fixes require an owner-controlled redeploy; the current production deployment is audited separately.
