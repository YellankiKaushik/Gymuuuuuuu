# Phase 17 local backup and restore decisions

The Phase 17 DOCX and JSON schema/reference data are normative. The expected Phase 17 Markdown file is absent from `DOCS_for_entire_apppliaction/GYM`; that omission is recorded in `docs/phases/17-plan.md`.

1. Preserve the database layout found in deployed code. Existing modules open seven databases (`fitness-os`, `fitness-os-local`, `fitness-os-diet-planning`, `fitness-os-recipes-meal-plans`, `fitness-os-recovery-sleep-mobility`, `fitness-os-cardio-conditioning`, and `fitness-os-supplements-evidence`). Moving stores into one database would require risky migrations and is unnecessary for a portable backup.
2. Inventory databases and stores at runtime where the browser supports `IDBFactory.databases()`. Back up all stores in discovered Fitness OS databases, carrying unregistered stores opaquely instead of dropping them. Databases whose names are not recognized are reported for review and are not opened or exported.
3. Treat the reference registry as logical ownership guidance, not as a complete physical schema. In particular, preserve Phase 15's two extra stores and the `fitness-os-local.records` store. Never guess unknown key paths or rewrite relationships.
4. Default portable backup excludes rebuildable caches, ephemeral timers, binary blobs, active-workout pointers, and tab-owner tokens. Full-media backup is explicit. Unknown database fields remain intact inside records because the browser's structured clone is carried as type-tagged JSON; unsupported values fail preflight before any download or restore.
5. Use canonical sorted serialization and SHA-256 hashes to detect accidental corruption. Hashes do not encrypt or authenticate data. Encryption remains a declared optional profile and is deferred until a separately reviewed cryptographic implementation can be tested against the schema.
6. Validate the whole archive and all selected target databases before beginning restore. Each database restore uses a single IndexedDB transaction; because the browser cannot atomically transact across databases, a durable journal describes partial progress and the UI blocks normal retries until the user resumes or rolls back.
7. Never send personal records to a server. Backup creation, restore, CSV conversion, quota estimates and persistent-storage requests run only in the browser.
8. Full-media records are included explicitly as typed inline Blob values in the validated JSON envelope, with separate per-asset length and SHA-256 entries. The reference prefers a ZIP package for full media; adding a ZIP reader/writer would expand dependency and archive attack-surface. This implementation therefore records that packaging change and retains the same explicit opt-in, media integrity and restore checks. Gzip remains a separate compressed JSON profile.
9. Module selection is performed at the physical database boundary because the existing modules own separate databases. The archive retains logical phase ownership in module payloads and the original database/store identifiers. Import-as-copy remains unavailable until every owner has a reviewed stable-ID and relationship remapper.
