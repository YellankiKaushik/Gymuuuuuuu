# Phase 09 snapshot, safety and storage decisions

The owner authorizes sequential implementation and a verified push after each phase. Supplied Lovable Plan-mode prompts do not introduce a new approval gate.

The normative schema requires full inputs and constant current versions, while the specification requires optional input storage and historical-version preservation. Generated normative schemas remain unchanged. A strict local/export snapshot extension permits null inputs and bounded historical version strings. New full-input plans use the supplied versions. Current-version inputs/results are checked numerically; historical snapshots keep their values and display a version warning. Unknown fields are rejected. Redaction removes explicit inputs and the protein-basis weight string; target outputs still reflect the selected assumptions and are personal records. No input reconstruction is offered.

Direct manual calorie overrides must remain within the standard -20 to +15 percent envelope, require a reason, and preserve the original maintenance estimate. This interprets the specified standard safety range consistently for both percentage and direct entry. The unrounded target is checked against the 1,000 kcal boundary before rounding. Headline rounding uses 25 kcal; macros reconcile to that rounded target. Custom meal totals allow 5 kcal and 0.1 g differences, and each meal's energy must reconcile with its macros within 5 kcal.

Use a separate version-1 fitness-os-diet-planning IndexedDB database with dietPlans, dietPlannerSettings and dietPlanAuditLog stores. This preserves the already released workout database and generic records database without altering their migrations. Phase 17 must register this additional database in unified backup/restore. A single read/write transaction validates mutation inputs, reads current snapshots, updates current selection and records audit. Concurrent current selection remains singular; stale metadata changes are rejected by updatedAt. BroadcastChannel carries only a change notification, never personal fields.

The earlier /diet path redirects to /diet-planning. Navigation aliases now resolve to the canonical implemented planner; the shell alias regression expectation is updated accordingly. No earlier module's record or calculation is replaced.

Reviewed food and population-intake releases remain empty. Targets are deterministic calculations from supplied Phase 09 constants; no food composition or Phase 08 intake row is invented. Optional Mifflin comparison, sports carbohydrate education and numeric hydration references are omitted as permitted optional scope. No service worker or installable offline shell is added in this phase; loaded calculator code/reference data runs locally without runtime APIs.
