# Verified content and review levels

The owner's Phase 19 request extends the original release scope to repository-owned content ingestion. Existing IDs, slugs and domain contracts remain authoritative. Internal legacy `published`/`approved` flags are admission/validation flags; they must not be presented as evidence of independent human or clinical review.

The completion layer records explicit states: draft, source_verified, machine_validated, human_review_pending, published_personal_use, published_reviewed and deprecated. Personal-use publication requires approved source rights, retained source locators/version and extraction dates, complete factual field/claim mappings, automated schema/reference/numeric validation and a visible review-level notice. Human-reviewed publication requires a real recorded human review and may not be generated by Codex.

USDA FoodData Central is the distributable composition source. April 2026 Foundation Foods is preferred when the specific identity/state is available; April 2018 SR Legacy is a labelled historical fallback. Exact source descriptions and per-100-g values are retained. A value's derivation and data points must not be misrepresented as a new measurement. Missing rows remain unavailable, explicit numeric zero remains zero, and trace remains unquantified. No raw/cooked conversion or serving mass is inferred from a name.

ICMR-NIN/IFCT is reference-only without documented reproduction permission. Unmatched Indian varieties are not silently replaced with vaguely similar USDA entries. Food matches require an explicit identity/state decision and a retained reason; automatic fuzzy matches are suggestions only.

Educational summaries cite the precise supporting material and preserve populations, limitations and uncertainty. Copyrighted technique guides are summarized with citations rather than copied in bulk; their images are not imported without reuse permission. Original project diagrams and recipe instructions must be identified as original; cooking yield cannot be called measured without a measurement, and retention factors cannot be invented.

Sources: [USDA dataset downloads](https://fdc.nal.usda.gov/download-datasets/), [USDA public-domain use policy](https://fdc.nal.usda.gov/api-guide/), [OpenStax book licensing](https://openstax.org/books/anatomy-and-physiology-2e/pages/preface). OpenStax is excluded from this automated ingestion: its current terms additionally restrict use in generative-AI offerings without prior permission. No OpenStax content or images are published. Its CC BY-NC-SA terms must not be relabelled CC0 or unrestricted commercial use.

Food composition shards are static repository-owned JSON assets requested from the same application origin with credentials omitted. URLs are constrained to local public-asset paths; response status and complete food schemas are validated before use. Rejected loads are evicted from the promise cache and the diary offers an explicit retry without changing saved records. A separate public-data transfer budget supplements the unchanged JavaScript budgets. The global search index loads when search is opened.

Generated recipe, food and nutrition schemas use Zod's built-in ISO date/timestamp validators directly instead of constructing a new validator for every nested value. This preserves the same offset and calendar validation. Nutrient definitions use an immutable ID lookup; positive IANA timezone validation has a bounded cache because ICU's identifier registry does not change during a process. Invalid identifiers are never cached as valid. The existing 100-ingredient/336-item stress test and its time limits remain unchanged. Generator `--schema-only` mode preserves published data and manually verified identity aliases during regeneration.

Browser completion reports retain the public index manifest and production build timestamp. Results from a different build or index are excluded. Unmeasured routes remain unmeasured; a current-build failure never becomes a pass because a previous run passed. Tablet evidence measures layout overflow, while mobile and desktop themes receive automated WCAG scans. These checks do not claim manual screen-reader or device testing.
